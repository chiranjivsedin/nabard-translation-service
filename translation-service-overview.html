NABARD Translation Service

FastAPI backend for English → Hindi notesheet translation via local Ollama model

Python 3.10+ FastAPI Ollama nabard-translator Port 8000

The frontend sends plain English text to POST /translate. The backend forwards it to Ollama and streams back the Hindi response. Glossary pre-processing (known term replacement) and artifact stripping ("Translation:" prefix removal) are applied in the frontend hook useNotesheetTranslation.js before the text reaches this service.

API Reference

GET /health

Check service health and Ollama reachability. Always returns HTTP 200.

// Response when Ollama is running and model is available
{
  "status": "ok",
  "ollama": "ok",
  "model":  "nabard-translator"
}

// Response when Ollama is down
{
  "status": "ok",
  "ollama": "unreachable: All connection attempts failed",
  "model":  "unknown"
}

POST /translate

Translate English text to formal Hindi (Devanagari script).

// Request
{
  "text": "The Notesheet has been approved by the Department."
}

// Response
{
  "hindi": "टिप्पणी पत्र को विभाग द्वारा अनुमोदित किया गया है।"
}

Error Responses

StatusReasonDetail message
422 Empty or missing text field text must not be empty
503 Ollama is unreachable Ollama service is unreachable. Ensure Ollama is running.
504 Ollama timed out Ollama did not respond within 120 seconds.
502 Ollama returned error or empty response Ollama error: <status> / Ollama returned an empty translation.

Setup & Running

# 1. Install dependencies
pip install -r requirements.txt

# 2. Copy and edit config
cp .env.example .env

# 3. Build the Ollama model (run from nabard-modern-ui directory)
ollama create nabard-translator -f Modelfile
ollama list   # verify it appears

# 4. Start the server
python -m uvicorn main:app --port 8000 --reload

# 5. Check health
curl http://localhost:8000/health

# 6. Test translation
curl -X POST http://localhost:8000/translate \
  -H "Content-Type: application/json" \
  -d "{\"text\": \"The Notesheet has been approved.\"}"

Production Notes

In production, Ollama runs on the application server — not the user's browser machine. The only change needed is:

  • Set OLLAMA_URL in .env to the production Ollama server address.
  • Set CORS_ORIGINS to the production frontend domain.
  • Update TRANSLATE_API_URL in the frontend hook to the deployed backend URL.
  • Deploy this service alongside the existing Java/Spring backend (same Tomcat or a separate process).
  • Optionally place it behind the existing authentication layer — the service itself has no auth.
